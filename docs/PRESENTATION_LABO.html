2. Data Pipeline

End-to-end flow from attack generation to dashboard visualization.

Pipeline stages:

  1. Attack generation - ParrotOS launches nmap scans, hping3 SYN floods, hydra bruteforce, and ICMP floods against the Target
  2. Detection - Suricata IDS on the Target captures attack traffic via af-packet interface and generates alerts in eve.json
  3. Alert forwarding - Wazuh Agent monitors eve.json and forwards alerts to Wazuh Manager on UDP 1514
  4. Alert storage - Wazuh Manager writes all alerts to /var/ossec/logs/alerts/alerts.json (57,027 lines)
  5. ML Inference - wazuh-inference service monitors alerts.json in real-time, extracts 36 features, runs XGBoost model
  6. Prediction storage - Results stored in SQLite database at /tmp/predictions.db (64,295 predictions)
  7. OpenSearch sync - wazuh-ml-sync service pushes new predictions to OpenSearch every 30 seconds
  8. Dashboard - Wazuh Dashboard displays real-time visualizations at https://192.168.30.3:443

5. Model Features

Top features used by XGBoost to classify alerts as True Positive (attack) or False Positive (benign).

The two dominant features are count_srcip_15min and count_rule_15min - the frequency of alerts from the same source IP and same rule within 15 minutes. This tells us the model identifies attacks based on alert burst patterns rather than individual signatures: sustained attacks generate many similar alerts in a short timeframe, while benign traffic produces isolated events.

10. Next Steps

  • Improve attack library - Add more attack types (web app attacks, reverse shells, DNS tunneling) to enrich training data
  • Optimize feature engineering - The current O(n-squared) feature extraction needs optimization for full dataset training
  • Deploy sustained attacks - Longer duration attacks would generate more True Positives and improve model balance
  • Real-time dashboard auto-refresh - Enable automatic dashboard refresh to see predictions arrive live
  • Alert correlation - Integrate with Wazuh rules to correlate ML predictions with existing detection logic
